# Marketplace AI Bot

Telegram-бот на базе локальной LLM для консультирования продавцов на маркетплейсах.

Бот работает локально и использует LLM через Ollama. Архитектура проекта включает маршрутизацию запросов, RAG по базе знаний, анализ изображений, function calling и MCP-инструменты.

## Возможности

* консультации продавцов по работе с маркетплейсами;
* специализированные сценарии:

  * экономика товара;
  * маркетинг и реклама;
  * карточка товара;
  * общая поддержка;
* работа с контекстом диалога;
* очистка контекста текущего диалога;
* маршрутизация запросов между специализированными сценариями;
* RAG по локальной базе знаний;
* анализ изображений и скриншотов;
* локальная LLM через Ollama;
* tools / function calling;
* MCP Server и MCP Client;
* MCP-инструмент для расчёта экономики товара;
* проверка аргументов инструментов перед выполнением;
* защита от использования выдуманных пользователем числовых данных;
* prompt engineering:

  * zero-shot prompting;
  * few-shot prompting;
  * role prompting;
  * structured reasoning;
  * инструкции по скрытию внутреннего хода рассуждений;
* логирование и трассировка запросов;
* генерация Request ID для отслеживания запросов;
* измерение времени обработки LLM-запросов;
* подсчёт prompt, completion и total tokens;
* обработка ошибок подключения к LLM;
* автоматические тесты.

## MCP

В проекте реализована интеграция с Model Context Protocol.

Доступный MCP-инструмент:

```text
calculate_margin_tool
```

Инструмент рассчитывает:

* прибыль;
* маржинальность;
* наценку.

Пример:

```text
Цена продажи: 2500 ₽
Себестоимость: 1500 ₽

Прибыль: 1000 ₽
Маржинальность: 40%
Наценка: 66.67%
```

Перед выполнением инструмента проверяется, что числовые значения были явно предоставлены пользователем. Если модель пытается использовать придуманные значения, вызов инструмента отклоняется.

## RAG

Для получения дополнительного контекста используется RAG.

Основные этапы:

```text
Пользовательский запрос
        ↓
Создание embedding
        ↓
Поиск релевантного контекста
        ↓
Формирование prompt
        ↓
LLM
```

Для хранения и поиска используются локальные данные и ChromaDB.

## Vision

Бот поддерживает обработку изображений и скриншотов.

Изображение может использоваться как дополнительный контекст для анализа продавцом:

* карточки товара;
* рекламных показателей;
* интерфейсов маркетплейсов;
* другой визуальной информации.

## Prompt Engineering

Для разных типов запросов используются специализированные системные инструкции.

Реализованы следующие техники:

### Zero-shot

Модель получает задачу без заранее заданных примеров.

### Few-shot

Для сценария экономики товара используются примеры корректного поведения модели:

* использование инструмента при наличии цены и себестоимости;
* запрос недостающей себестоимости;
* запрос недостающей цены.

### Role Prompting

Для разных направлений используются отдельные роли:

```text
economics
marketing
product_card
support
```

### Structured Reasoning

Для обработки запроса модель получает структурированный алгоритм:

1. определить тип задачи;
2. выделить предоставленные пользователем данные;
3. определить недостающие данные;
4. определить необходимость инструмента;
5. использовать только подтверждённые данные;
6. проверить результат инструмента;
7. сформировать итоговый ответ.

Внутренний ход рассуждений модели не выводится пользователю.

## Логирование и метрики

Для каждого LLM-запроса создаётся уникальный `Request ID`.

В логах фиксируются:

* маршрут запроса;
* вызовы инструментов;
* аргументы инструментов;
* результаты MCP;
* ошибки;
* latency;
* prompt tokens;
* completion tokens;
* total tokens.

Пример:

```text
LLM tool request completed
request_id=74b9c3a1c962
latency=8.71
prompt_tokens=2613
completion_tokens=70
total_tokens=2683
```

## Запуск

Установить зависимости:

```powershell
pip install -r requirements.txt
```

Запустить Ollama и убедиться, что необходимая модель установлена.

Активировать виртуальное окружение:

```powershell
.venv\Scripts\activate
```

Запустить бота:

```powershell
python -m app.main
```

## Тестирование

Проверка синтаксиса:

```powershell
python -m py_compile app/services/llm_service.py
python -m py_compile app/tools/validator.py
```

Запуск тестов:

```powershell
pytest
```

Для проверки MCP предусмотрен отдельный сценарий тестирования.
